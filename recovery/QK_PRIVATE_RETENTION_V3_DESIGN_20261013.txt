QK Candidate B: independent private-retention v3 (source only)
2026-10-13

Scope
Retain the warm-handle route and all existing native arithmetic. Omit only the
six allocator recordStream registrations for qn/kn/qs/ks/qrope/krope. This is a
new native binary/namespace, not the frozen v2 binary or a requalification of it.
No build, device correctness, speed or model admission is inherited.

Actual allocate_call owner order for with_send=true
0..4: raw, query weight, key weight, expanded cosine, expanded sine.
5..10: qn, kn, qs, ks, qrope, krope (six distinct private allocations).
11..13: padded output owner, send view, V view.
Cold with_send=false owns only the first eleven; no cold allocation changes.

Before reclaim, recordStream or queue submission, v3 checks fourteen owners,
exact TensorImpl identities against the actual source/native output objects,
and distinct StorageImpl for each private allocation against all other owners.
The existing full native descriptor/extent checks still precede this block.
Indices 0..4 and 11..13 retain their original registrations, including original
alias duplicates. Full owners, ins/outs and fresh allocations remain unchanged.
Runtime owner checks are included in the measured complete-call cost.

Lifetime proof and limits
The original queued_calls and callback [p,c] retain Call before submission;
plan.active retains it after callback selection. All native computation and
pack use the original bound default stream. The event is recorded after pack.
Only a same-consumer-thread RECORDED event with matching recorded_generation
may be queried. COMPLETE permits retirement; producer reclaim releases only
retired Calls. Generation, event query, fixed capacities, retirement, allocator
ownership, failure quarantine, close and producer finalize are unchanged.
No private allocation reaches HCCL; source, send/owner and V protections remain.
Producer reclaim TID does not prove the last Tensor destructor thread because
the framework may also retain and release callback captures independently.

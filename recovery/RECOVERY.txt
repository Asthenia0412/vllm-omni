Reimplemented missing runtime dependencies
-----------------------------------------
csrc/lingbot_recovery/ contains versioned source for:
  - Actual NPU storage descriptor, including physical format and full extent.
  - One C++ QK entrypoint: native BF16 RMSNorm and interleaved RoPE followed by
    an Ascend C send pack [8,585,3,1,5,128]. Fresh output per call.
  - BF16 cross-attention C++ validation/native BSND FIA dispatch, H40/D128.
  - Ascend C recv-to-dense-Q/current-KV-pool/staging, H5/D128, actual capacities.
  - Bit-preserving 4D/5D row-strided pair copies; 5D VAE model integration.

The QK arithmetic uses public native operators; it does NOT reproduce the
lost custom RMS/RoPE OPP binary or claim its exact kernel schedule/performance.
The 4D copy primitive is tested, but the old independent 4D VAE experiment is
not automatically enabled. The candidate enables the reconstructed 5D path.
The old custom attention resident-O/UnitFlag experiments remain unadmitted.

All reconstructed features default off. New config keys are
lingbot_npu_recovery_{qk,cross,vae_pack,descriptor}. Old provider flags cannot
enable these paths, and old binary SHA/admission claims are never inherited.
Runtime loading checks source, ABI-header and binary hashes, loaded kernel
dependency, framework versions, actual SoC and runtime policy. The kernel
target is Ascend910_9392/arch22, with at most 32 KiB UB per Vector core here.
The framework queue callback uses stream(false), avoiding a recursive queue
drain. Kernel submission errors propagate. Owners are retained and recorded
on their consuming stream. Pool ownership and scratch/managed page authority
remain with the original manager; no new cache commit logic is introduced.

recovery/supervise.py owns a fresh uid/pgid/start-time/nonce-scoped service and
retires all its workers after a fatal record or service exit. It never selects
or signals another job by executable name or NPU number.

Build and configuration
-----------------------
  cd /mnt/sfs_turbo/lingbot-recovery-zhoutaichang-20261012/worktree
  source recovery/env.sh
  bash recovery/build.sh
  bash recovery/check_all.sh

env.sh exposes LINGBOT_RECOVERY_ROOT, LINGBOT_CANN_ROOT and LINGBOT_VENV for
relocation. The installed SDK/venv must match the pinned versions. Rebuild
after relocation; manifests bind actual source and library paths.
Each build uses a fresh directory because the SDK's legacy incremental linking
rewrites object files in place. Previous DSOs are retained. The latest manifest
path is written to ../build/latest-manifest.txt after successful registration.

  python recovery/make_config.py --output recovery/native.yaml
  python recovery/make_config.py --candidate --output recovery/candidate.yaml

native.yaml uses retained native operations for missing library routes and
disables StageA. It keeps the other recovered Python optimizations, including
FFN W8A8 and primary-only pixel output. candidate.yaml opts into the rebuilt
paths and StageA. Neither configuration contains a missing /mnt/data library.

After weights finish and physical NPUs 0-3 are verified free, a correctness
service can be started with:

  ASCEND_RT_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 python recovery/supervise.py \
    --runs "$LINGBOT_RECOVERY_ROOT/model-runs" --mode correctness --recv \
    --manifest "$(cat "$LINGBOT_RECOVERY_ROOT/build/latest-manifest.txt")" -- \
    vllm serve "$LINGBOT_RECOVERY_ROOT/models/lingbot-world" --omni \
    --deploy-config recovery/candidate.yaml --port 7816 \
    --init-timeout 1800 --stage-init-timeout 1800

For rollback use native.yaml and omit --recv. The new candidate remains an
experimental reconstruction until model, lifecycle, quality and timing gates
pass. Keep BF16 attention, four DMD steps, full history and actual 12 FPS.

    recv actual pool capacities, full pool/staging comparisons; QK and cross
    bitwise comparison with native arithmetic; descriptor extent/address.
  - HCCL: all eight ranks matched the original complete All-to-All output
    bitwise; reused send leases rejected; supervisor exited with zero owned
    processes left alive.

These use synthetic operator inputs. They do NOT replace real-model descriptor
capture, four-probe/six-history coverage, paired 80-chunk latent/RGB checking,
video quality, lifecycle or performance tests. No reconstructed model FPS or
latency result is claimed. Historical ~895-899 ms results belong to the old
lost binary combination, not this rebuild.

Existing environment logs also contain optional Triton constexpr_function and
libz3/libstdc++ compatibility warnings. Eager model import and the tested native
paths work; graph/compile routes require separate compatibility validation.

It seals plan.json and one launch.sh per stage. The complete order is
  correctness-A, correctness-B, compare, timing-A1, timing-B1, timing-B2,
  timing-A2, timing-A3, timing-B3.

  python recovery/run_cross_model_screen.py --plan <directory>/plan.json \
    --stage correctness-A --run <A-owned-supervisor-directory> --adopt-completed --execute
  python recovery/run_cross_model_screen.py --plan <directory>/plan.json \

paired workload is not a replacement for all video-quality/lifecycle acceptance.

For each timing stage, in the order above:
  bash <directory>/<stage>/launch.sh
This foreground launcher first runs source/pin/previous-stage preflight, clears
inherited selected policy/capture/profile variables, restores the pinned ordinary
A environment, and execs the existing supervise.py. It prints its owned run path.
In a separate terminal/controller, still in MAIN with recovery/env.sh sourced:
  python recovery/run_cross_model_screen.py --plan <directory>/plan.json \
    --stage <stage> --run <printed-owned-supervisor-directory> --execute
The controller invokes the existing run_timing.py exactly once: fresh warm40,
then fresh161 request,12FPS actual encoding. It checks actual seed42,forward
camera,flow_shift5,832x480,complete chunk/frame order,commands/image and model,
then retires only that launch's uid/pgid/start identity. Each later timing service
must start after the previous controller-observed retirement BOOTTIME boundary.
No capture service is reused for timing. The default without --execute performs
preflight only; no request, comparison, process retirement or device call occurs.

Resume is per stage. Completed stage.json is revalidated and skipped. For a
completed request whose original controller ended before receipt finalization,
use the SAME --run with --adopt-completed and the saved live environment plus
retirement evidence. Never resend a request to an already used service. Partial
or failed requests are not automatically retried: preserve their files and use a
new explicitly prepared attempt. Invalid/untrusted startup evidence yields
failure.json with needs_manual_retirement; unknown processes are never killed.

Persistent model services may exit-15/-9 after successful requests because the
owned supervisor retires every worker. Such a code alone is not accepted: the
stage also requires a passing request, no fatal report, no remaining owned
processes and a bound prior retirement intent. Other exits remain failures.

Every stage binds plan/config/build/controller sources, launch/result, selected
live environment, raw rollout and request command. Timing adds warm40 and161
protocol evidence. Correctness binds capture request IDs and fresh payload dirs.
The plan pins workload/default-seed source and the already-passing model-integrity
SHA; it does not claim a fresh rehash of all model weights. Environment scope is
selected LingBot/thread/device/allocator policy, not every inherited process
variable or complete loader PATH/LD_LIBRARY_PATH. No CPU/NPU policy is tuned.

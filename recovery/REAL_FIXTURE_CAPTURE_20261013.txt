OWNERS AND FAILURE CONTRACT
Each snapshot records eleven C++ storage descriptor fields: physical/origin
format, base shape/stride, physical sizes, view shape/stride, storage offset,
allocation byte count, allocation origin pointer and view pointer. Dtype, element
size, device, logical bytes and available version counter are added.

For admitted unblocked formats0/2/30, require dense physical base, no hidden
extent, byte count exactly equal to the complete allocation, valid positive
view spans and pointer+offset agreement. A full-owner as_strided view reads from
storage origin. No format labels are mutated and logical input views are not
replaced. This readback path is CPU-reviewed; live NPU admission still needs the
smoke above. Unsupported/invalid descriptors fail the correctness request.

All selected layer0 input owners are read before AND after the original call;
full raw bytes and descriptors must be identical. Output owners are read after
the original call. Strong references remain live through readback/call/consumer;
on failure the original tensors/traceback are quarantined and the existing fatal
channel requests all-eight-worker retirement. There is no poststart fallback.

Metadata-only layers claim descriptor/version stability, not source byte proof.
Capturing a full owner does not prove a future candidate destination's canary:
all cases explicitly mark destination_canary_verified=false. Candidate screening
must allocate its own complete arenas/canaries and validate their entire bytes.
No KV pool or staging arena payload is copied by this QK/cross fixture mode;
manager capacities, block IDs and owner identities are recorded for context.
Recv/KV arena correctness is a separate campaign.

FILES / REPLAY SCHEMA
  rankR/coverage.json
  rankR/qk_kv4680_p0_l00.json ... cross_kv28080_p3_l39.json
  rankR/owners/<sha256>.u8
QK inputs: qkv, query_weight, key_weight, cosine, sine, expanded_cosine,
expanded_sine. Output: native_send. Cross inputs: query,key,value. Output:
native_output. JSON inputs/outputs each contain descriptors, owners and
view_owner_ids. Owner IDs are scoped to the case AND section. Content-addressed
files deduplicate immutable bytes, but equal content hash is NOT owner identity;
live allocation pointers determine aliasing within a snapshot.

Minimal CPU reconstruction example (not a device admission):
  case = json.loads(case_path.read_text())
  snap = case['inputs']; cpu_owners = {}; tensors = {}
  dtype_map = {'torch.bfloat16':torch.bfloat16, 'torch.float32':torch.float32}
  for name, d in snap['descriptors'].items():
      oid = snap['view_owner_ids'][name]
      if oid not in cpu_owners:
          owner = snap['owners'][oid]
          raw = (case_path.parent / owner['relative_path']).read_bytes()
          assert len(raw) == owner['storage_bytes']
          assert hashlib.sha256(raw).hexdigest() == owner['raw_sha256']
          cpu_owners[oid] = torch.frombuffer(bytearray(raw), dtype=dtype_map[d['dtype']]).clone()
      tensors[name] = cpu_owners[oid].as_strided(d['shape'],d['stride'],d['storage_offset'])
Keep cpu_owners alive. Device replay must allocate the complete owner once,
create all views from that owner and independently revalidate its physical
format/extent/strides/offsets before invoking the candidate. A logical contiguous
clone is insufficient to reproduce the original storage contract.

Unresolved v1 ownership boundary
The consumer callback performs plan.active.reset(), and close destroys Tensor
owners/workspaces. If this releases the last reference to recordStream-managed
storage, allocator free/event insertion can enqueue work onto the same consumer
queue. A full queue could therefore cause the consumer to wait on itself.
This is a source-review risk; this run did not reproduce such a failure or establish
it as a latency cause. External ownership plus two drained calls does not prove
safe last-reference release or queue-saturated execution. Preserve these v1 files
and evidence; resolve ownership in a separately named/pinned v2 before expanding.

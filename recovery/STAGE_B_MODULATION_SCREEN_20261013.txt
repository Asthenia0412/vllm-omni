New mechanism
StageA retains the original three-row BF16 timestep outputs. The block still
performs parameter.unsqueeze(1) + projection.float(), then chunk(6,dim2),160
times/chunk. StageB independently caches the original FP32 result and its six
original views per layer/probe/session. It preserves mixed BF16+FP32 add order.
It changes no norm, attention, FFN, rounding, camera, KV, VAE or head arithmetic.

Implementation is default-off: lingbot_npu_fixed_modulation_stageB=false.
Original StageA bytes and all228 historical top-level engine/distributed/
entrypoints/worker Python files remain unchanged. Pipeline/transformer hooks
and an independent helper carry the new behavior. Reserve24MiB per session
before KV sizing; at most2 session banks, counting actual allocation extents.
Published StageA source identity and real DMD capabilities authorize reuse.
All160 entries and four successful all40/head/gather/unpatchify forwards must
complete before B hits are enabled. Retirement deactivates B before StageA's
original stream drain; B owners release only after that drain/removal succeeds.
Exceptions retain owners, poison the worker and report through restart8 fatal
supervision. No candidate-started fallback or installed-OPP change is introduced.
